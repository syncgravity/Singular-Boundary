## Remote verification

After review and an authorized push, verify the LFS attributes and exact object retrieval from a fresh clone:

1. Install Git LFS hooks in the checkout with `git lfs install`.
2. Check attributes with `git check-attr filter -- data/raw/<filename>`.
3. Clone `origin` into a new directory and run `git lfs pull`.
4. Recompute each imported object's SHA-256 and compare it with the intake manifest.
5. Mark remote availability or clean-checkout verification complete only after those checks pass.

If storage quotas make LFS unsuitable, use immutable content-addressed external storage and commit checksums plus an access policy. Do not claim that a GitHub commit containing only a manifest has uploaded the scientific data itself.
