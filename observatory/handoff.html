How the Observatory maintains itself

The Observatory is a maintained index of source records and repository state, not a static narrative. Every maintenance pass must be reproducible, source-preserving and explicit about what it does not certify.

  1. Read before editing. Start from this handoff, then inspect the current main SHA, all open PRs, the live branch refs, theorem registry, Proof Atlas data and the S0–S5 program. Treat dates and counts on this page as a snapshot, never as live facts.
  2. Inventory before consolidation. For every open PR, record its base/head SHA, commit list, changed paths, checks, review state and whether its head is already contained in main or another consolidation branch. Compare file content and Git blob hashes, not titles or branch names alone.
  3. One integration PR, no content loss. The target is one open integration PR. Do not close a PR until every unique commit and artifact has been merged or faithfully consolidated into that integration branch or main, with source paths, hashes, verifier scripts, logs and provenance preserved. If two versions conflict, retain both as dated source records and document which is current; do not silently overwrite. Keep independent mathematical models and their assumptions separate.
  4. Close only after destination verification. Confirm that every changed path from the retiring PR exists in its destination, compare relevant blobs or inspect the consolidated commit, rerun its applicable checks, and update the lifecycle ledger with source PR, destination commit and disposition. Closing a PR must never be used as a substitute for integration.
  5. Validate the Observatory. Run the theorem-source verifier, graph/catalog builders and validators, JavaScript syntax checks, and branch-retirement dry-run. Rebuild generated files from canonical inputs rather than hand-editing generated output. Check internal links and all source references. A failed check blocks merge; fix the source/index mismatch rather than inserting an empty placeholder or weakening the verifier.
  6. Refresh the handoff last. After consolidation, update the branch and PR inventory, source counts, latest main and integration SHAs, outstanding CI failures, and exact next proof objective. Preserve the previous snapshot in the dated lifecycle history. The next session should be able to begin here without relying on chat history.
  7. Retire refs conservatively. Use the SHA-checked manual retirement workflow in dry-run mode first. Only refs whose exact heads are already ancestors of main are eligible; open PR heads/bases and all unmerged research branches remain protected. Review the eligible/withheld output before any retirement run.

Maintenance invariant: every claim, calculation, counterexample, verifier, log and historical source has a traceable durable destination. The Observatory may reorganize navigation and identify superseded work; it must not erase research history, promote a theorem by indexing, or conflate distinct regulator/model assumptions.
