This protocol is required whenever a user names files, asks to continue a prior proof/review, or refers to “the records,” “your earlier work,” or an established source dossier.

2. **Enumerate paths before judging presence.** Read the complete recursive Git tree for the target branch (`GET /repos/{owner}/{repo}/git/trees/{branch-or-sha}?recursive=1`). Match exact filenames, case-insensitive names and distinctive stems. Report exact paths, not guessed paths.
3. **Check branches when a requested file is absent from the target branch.** Enumerate branch refs and inspect recursive trees of relevant topic/review branches. Do not create a new branch just to search. A branch name search is not a file search.
4. **Check source containers and custody records.** Inspect source manifests, archive-member catalogs and nested ZIP/TAR member listings where relevant. Distinguish: absent from branch tree; present only inside an archive; local-only; Library-only; inaccessible; and genuinely unlocated. Never call these states interchangeable.
5. **Read the complete file, not a search excerpt.** Fetch full contents by exact path and record the blob ID. For long files, read consecutive line ranges until EOF and mark the record complete only after the final range. For binary/container sources, inspect member lists and extract/read the named member; preserve the original bytes and hash.
6. **Build a session source ledger before synthesis.** For each requested item record requested name, exact path or unresolved status, branch/commit, blob ID or content hash, read status, and a one-sentence description. Keep source-derived statements distinct from later interpretation, independent proof, numerical control and open conjecture.
