# Run the Stage 9 SU(2) campaign locally (preferred for sustained work)

The eight 20-slice configurations **already exist** at four seeds in each of two geometries. They contain Haar-initialized gauge fields, exact continuation RNG states, Metropolis plaquette caches and warm-up histories. The Stage 9 archives record 206 combined warm-up sweeps; none were production observations. **Preserve a copy of these original ZIP files.**

1. Install Python >=3.10 and packages `numpy`, `scipy`, `numba`, `arviz`. A reliable SSD, 64-bit OS, adequate free disk, and preferably 16 GB RAM are practical recommendations, not rigorously benchmarked minimums. Set `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 NUMBA_NUM_THREADS=1`.
2. Extract `Penrose_YM_Stage9_Analysis_And_Resume_Code.zip` and **all four** `Penrose_YM_Stage9_Checkpoints_*.zip` archives into one parent directory. They contain paths beginning `ym_stage9/`; do not accidentally create `ym_stage9/ym_stage9/`. Keep the optional cold-start control separate.
3. Copy `stage9_local_batches.py` from the accompanying small add-on ZIP into `ym_stage9/` (where `stage7_checkpointed.py` resides). Then `cd ym_stage9`.
4. Verify `python -m unittest -q test_stage8 test_stage8_observables test_stage9_fit_tools test_stage9_requirement_audit test_stage9_coldinit` and `python stage9_requirement_audit.py --root checkpoints --output STAGE_9_ADMISSION.json`.
5. Dry-run `python stage9_local_batches.py --dry-run` to list all eight saved sweep counts without updating data.
6. First test `python stage9_local_batches.py --chunk 5 --passes 1 --verify-hash`. For a sustained run, `python stage9_local_batches.py --chunk 100 --passes 0 --max-hours 6 --verify-hash`. Repeat to continue. Each 100-sweep segment is atomically checkpointed; if interrupted mid-segment, the last saved segment remains usable. The driver logs completed segments to `stage9_local_batch_log.jsonl`. It holds a process lock to avoid overlapping invocations **of the local driver**.
7. Re-run the scientific audit regularly: `python stage9_requirement_audit.py --root checkpoints --output STAGE_9_ADMISSION.json`. Copy checkpoints and ledgers to separate backups while no worker is writing. Do **not** run a Slurm job targeting the same checkpoint while this local driver runs.

The source also includes `stage9_slurm_array.sh` for a cluster, with one chain per array task. On a local workstation prefer the serial driver initially, then measure memory and CPU use before launching parallel jobs. Native local driver uses POSIX `fcntl` locking (Linux/macOS/WSL); on Windows use WSL or the Slurm template under a Linux cluster.

**Interpretation and stopping rules:** `--target 10000` means 10,000 sweeps total **per chain**, including the provisional 1,000 thermalization sweeps; with `thin=10` this would yield up to 900 nominal post-burn observations per chain. Hot/cold stationarity, Rhat <1.01, bulk/tail ESS >=400 for the actual correlator channels, positive-conditioned scalar variational matrices, stable correlated fits, physical string-tension matching, alternative geometry controls and continuum scaling **must still be established**. A numerical sweep target does not certify any of these. The existing measurement engine's 100 spatial paths also do not automatically include the separately created 288-path long-distance extension. Run longer-path measurement separately only after code/data provenance is secured. All mass and continuum outputs remain null until independently admitted.

**Suggested return data:** the eight `*_progress.json` ledgers, `STAGE_9_ADMISSION.json`, the local batch log, and the post-burn per-configuration observables (or archived `.npz` checkpoints if storage/upload permits). No secret credentials or private system data are needed.
